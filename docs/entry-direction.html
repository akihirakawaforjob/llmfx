帯に来た時点では方向を決めない

いまの実装は、帯へ触れる前に売るか買うかを決めています。 仕様は「帯が何を示したかに従う」。この 1 行の差を図で確認します。

仕様

あなたの手順(CLAUDE.md より)

利用者
  1. 抵抗帯を見つける — 何度も試され、そのたびに押し戻されている水準
  2. 帯で待つ — 抜けた瞬間に飛び乗らない
  3. 帯が何を示したかに従う — 弾かれたら跳ね返りに乗り、抜けたら 抜けた側に乗る。帯に来た時点では方向を決めない
  4. 伸ばす — 固定の利確を置くとこの裾を切り落とす
実装との差 3 が入っていません。reverse_entry という設定で、 帯へ触れる前に向きが固定されています。 False なら必ず跳ね返りに賭け、抜けたら見送る。 True なら必ずブレイクに賭け、跳ね返ったら見送る。
場面 1

弾かれた場合 — 執行足が下へ折り返す

帯が跳ね返した帯 100.00 / ATR 0.10 / 執行 M15

帯へ触れた後、執行の足が 安値1 を下抜けたところで売り。 損切りは帯の外。この動きは今の実装でも取れます (reverse_entry=False のとき)。

場面 2

抜けた場合 — 執行足が上へ折り返す

帯を抜けた帯 100.00 / ATR 0.10 / 執行 M15

同じ帯へ触れた後、今度は執行の足が 高値1 を上抜けたところで買い。 この動きも今の実装で取れます (reverse_entry=True のとき)。

取れないもの 同じ設定で両方を取ることができません。 今の実装はどちらか一方に固定されるので、場面 1 用に設定すると場面 2 が見送られ、 場面 2 用に設定すると場面 1 が見送られます。
提案する規則

先に来たほうを取る

帯へ触れてから、両側を同時に見張る どちらか先に抜けたほうで入る
確認したいこと
  1. 見張る水準は執行足の直近の高値と安値でよいか (いまのドテン・買い増しと同じ基準)
  2. 同じ足で両方に触れたとき、どちらを採るか。 帯に近いほうが先に届いたと考える案でよいか
  3. 24 本(執行足)で打ち切るのは今のまま
  4. 損切りはどちらの向きでも帯の外。向きで変えない
