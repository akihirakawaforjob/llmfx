②
ダウ転換はどの足で見るか ダウ転換自体は同じ足で見る。しかし、エントリーポイントは2つ下の足で見ないと意味がなくなる。 → 構造は H1、執行は M15。足が2つに分かれる。
③

④

⑤
買い増しは何回まで、どれだけ これもいくつが最適か見たい。 → 掃引する軸にする。回数(0〜3回)と1回あたりの量。
⑥
動かない建玉はいつ閉じるか 動かない＝損になっていないので問題なし。 → 時間切れを外す。出口は「ダウ転換」と「損切り」の2つだけになる。

補足 1

抵抗帯の線は、こう引かれる

エントリーがこの線の上に乗るので、線の引き方がずれると全部ずれる。初版〜第2版はここを間違えていた。

H1直近1週間で最も高い「折り返した高値」。確定してから線になり、更新されれば動く
性質中身
何を線にするか直近 120本(1週間) の中で最も高い 折り返した高値。いま進行中の動きの端は使わない
いつ線になるか折り返しが確定してから。ピボットの右側の足が出るまで線は存在しない(先読みを避けるため)
線は動くか動く。より高い折り返しが出れば上へ。古い折り返しが1週間の窓から外れれば下へ
何回試されたか数えない。「4回以上」「6回以上」と要求を上げるほど単調に悪化した(3回測って3回とも)
弾きの強さ使わない。過去の弾きの中央値で絞ると、0.5→1.0→1.5 ATR で -0.107 / -0.108 / -0.118 と悪化した
なぜここを「抵抗帯」と呼ぶか

利用者が実際のチャート3枚(5分・15分・1時間)に引いた線が、どれもその足で表示されている窓の上端と下端だったため。スイングの塊ではなく、映っている範囲の外枠。足を変えれば線も変わるのはそのため。

「何度も試された水準ほど強い」という説明は、この作り方では成り立たなかった。効いているのは「1週間の端で、そこで折り返した」という事実だけ。

補足 2

指値を線の ± どちらへ置くか

エントリーは線の最値ちょうどを基準に、そこから ± いくつずらすかを掃引する。設定は entry_beyond_atr、いまは 0(線ちょうど)。

M15同じ値動きに、3つの置き方を重ねたところ
置き方値約定価格取りこぼし
奥(線の外側)+0.1 〜 +0.5届きにくい良い多い
線ちょうど(いま)0———
内側(手前)-0.1 〜 -0.5届きやすい悪い少ない
利用者の指定と、その反対側

「抵抗帯の少し奥(スプレッド対策)に予め指値を設定しておき」という指定があるので + 側が本命。入り側のスプレッドを線が吸収する形になる。

ただし奥へ置くほど約定しない。実測では 3.0 ATR 奥へ置くと件数が 3 割まで落ちた。±0.5 ATR の範囲を細かく掃く。

直した後

これで利確が損切りより手前に来るので、先に届くのは転換ラインのほう。帯から入った建玉とまったく同じ形になる。

安値4 が確定したら、損切りは 安値3 へ上がる。

要するに

「1つ前へずらす」という規則を、ドテンした建玉にだけ掛け忘れていた。帯から入った建玉には最初から掛かっている。掛け方を揃えるだけで、他は何も変えない。
